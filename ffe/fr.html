Lecteur de Résultats d’Escrime PHP / Parsing XML / Statistiques

Outil web développé pour la Fédération Française d’Escrime. Il lit automatiquement les fichiers de résultats officiels (exports XML), extrait les informations clés (matchs, classements, arbitres, performances) et les présente sous forme de tableaux lisibles pour les entraîneurs. Le but : éliminer toutes les manipulations Excel manuelles après chaque compétition.

01. Contexte Avant l’outil

Après chaque compétition d’escrime, la fédération récupère un fichier brut contenant tous les assauts, les poules, les tableaux d’élimination directe, les classements, les arbitres, etc. Avant ce projet :

  • Les responsables ouvraient ces fichiers à la main pour chercher qui a battu qui, avec quel score, à quel tour.
  • Ils copiaient/collaient les infos dans Excel pour reconstituer les classements et préparer un retour aux entraîneurs.
  • Chaque compétition demandait une reconstruction complète des tableaux. C’était lent et dépendant de la personne dispo ce week-end-là.

La demande : un outil rapide, fiable, utilisable par du personnel non technique.

02. Objectif Ce que j’ai livré

J’ai développé une interface web en PHP qui :

  • Analyse automatiquement les exports officiels de compétition (par ex. lille.xml).
  • Affiche les poules (poules.php), le classement final (classement_f.php), les feuilles de match (match.php), la liste des tireurs inscrits (inscrits.php) et la liste des arbitres (arbitre.php).
  • Calcule des indicateurs de performance (victoires, écart de touches, etc.).
  • Présente les résultats dans des tableaux HTML propres, prêts à être partagés avec les entraîneurs.

J’ai fait une démo en direct auprès du responsable fédéral, récupéré leur feedback (quels indicateurs sont vraiment utiles pour eux), puis ajusté le contenu et la présentation.

03. Approche technique Comment ça marche

  • Source unique : un seul fichier XML (ex : lille.xml) contient toute la compétition : poules, tireurs, arbitres, scores, classement.
  • Pages PHP dédiées : chaque fichier PHP correspond à une vue claire : poules.php pour les poules, match.php pour les matchs, classement_f.php pour le classement, inscrits.php pour les engagés, arbitre.php pour les arbitres.
  • Rendu HTML : les données sont affichées en tableaux propres avec un style commun (styles.css) pour que ce soit lisible par quelqu’un qui n’est pas développeur.
  • Pas de base de données : tout est calculé en mémoire à partir du XML → déploiement facile, réutilisable sur n’importe quelle compétition.

Concrètement : on dépose un nouveau fichier XML de compétition dans le dossier, et le site est prêt pour cet événement sans rien reprogrammer.

04. Stack technique Outils

  • PHP pour la logique, le parsing et les calculs d’indicateurs
  • SimpleXML pour lire les exports XML fournis par la fédération
  • HTML / CSS pour l’interface visible par les coachs et les arbitres
  • Architecture modulaire (plusieurs pages PHP spécialisées) pour obtenir des URL simples à partager

05. Impact Pourquoi c’est utile

Après mise en place :

  • La fédération peut générer un récapitulatif de compétition en quelques minutes, au lieu de refaire tout à la main sous Excel.
  • Tous les entraîneurs voient la même info, présentée de la même façon — plus de version contradictoire.
  • Les débriefs d’après-compétition se concentrent enfin sur la performance sportive, pas sur le ménage de la donnée.

Le projet m’a aussi appris à travailler avec des interlocuteurs non techniques (encadrement fédéral, arbitres), traduire « on veut des stats » en KPIs calculables, et formater l’info comme ils en ont besoin sur le terrain.

06. Spécification du besoin État des Besoins

Avant d’écrire la moindre ligne de code, j’ai rédigé un État des Besoins qui décrit toutes les pages attendues, les données à afficher et la navigation. En pratique, j’ai joué le rôle de chef de produit.

  • Accueil / index.php : nom de la compétition, organisateur, lieu, date, formule (ex : Poules → Élimination directe), statut en cours.
  • inscrits.php : liste des tireurs engagés avec nom, club, catégorie, arme. Avec recherche.
  • arbitre.php : liste des arbitres affectés à l’événement (nom, club, niveau).
  • poules.php : tableaux de poules complets, avec chaque assaut, les touches données/reçues, les victoires, et l’arbitre de la poule.
  • classement_f.php : classement intermédiaire et final, couleurs des médailles, tour d’élimination atteint.
  • match.php : vue détaillée d’un match ou d’une branche de tableau pour analyse avec l’entraîneur.

L’État des Besoins inclut aussi les évolutions futures :

  • Suivi des cartons / pénalités par tireur.
  • Statistiques d’arbitrage pour évaluer les arbitres.
  • Mise en évidence des surprises (une tête de série basse bat un favori).

07. Logique PHP principale Parsing XML

Ci-dessous un extrait simplifié de la logique utilisée dans poules.php : on lit l’export XML officiel (ex : lille.xml), on boucle sur chaque poule, puis on liste tous les matchs avec le score. 


// Charger les données de compétition
$xml = simplexml_load_file("lille.xml");

// Stocker toutes les poules
$pools = [];

foreach ($xml->Poule as $poule) {
    $poolNum = (string)$poule['Num'];

    // Infos structurées pour cette poule
    $pools[$poolNum] = [
        "referee" => (string)$poule['Arbitre'],
        "matches" => []
    ];

    // Boucle sur chaque match de la poule
    foreach ($poule->Match as $match) {
        $fencerA = (string)$match->TireurA['Nom'];
        $fencerB = (string)$match->TireurB['Nom'];
        $scoreA  = (int)$match['ScoreA'];
        $scoreB  = (int)$match['ScoreB'];

        $pools[$poolNum]["matches"][] = [
            "a" => $fencerA,
            "b" => $fencerB,
            "sa" => $scoreA,
            "sb" => $scoreB
        ];
    }
}

// Rendu HTML de chaque poule
foreach ($pools as $num => $data) {
    echo "<h2>Poule " . $num . " (Arbitre : " . $data["referee"] . ")</h2>";
    echo "<table>";
    echo "<tr><th>Tireur A</th><th>Tireur B</th><th>Score</th></tr>";

    foreach ($data["matches"] as $m) {
        $scoreLine = $m["sa"] . " - " . $m["sb"];
        echo "<tr>";
        echo "<td>" . $m["a"] . "</td>";
        echo "<td>" . $m["b"] . "</td>";
        echo "<td>" . $scoreLine . "</td>";
        echo "</tr>";
    }

    echo "</table>";
}

Le même principe est réutilisé ailleurs : classement_f.php parcourt le classement final, arbitre.php parcourt les arbitres, inscrits.php parcourt les tireurs engagés, etc. Pour une nouvelle compétition, il suffit de remplacer le fichier XML.
