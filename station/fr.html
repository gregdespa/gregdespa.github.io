Station météo connectée Arduino • XBee • Capteurs

Station météo basée sur deux Arduino, avec liaison radio XBee et actionnement automatique. Un Arduino (Émetteur) lit la température, l’humidité, le vent et la luminosité puis envoie ces données via XBee. L’autre Arduino (Récepteur) affiche les valeurs sur un écran LCD / clavier et pilote des servomoteurs pour ouvrir ou fermer les volets selon les conditions.

01. Vue d’ensemble Architecture

Le système est séparé en deux modules physiques :

  • Émetteur (E) : lit tous les capteurs météo et envoie les mesures via une liaison radio XBee point-à-point. C’est la “sonde extérieure”.
  • Récepteur (R) : reçoit les trames XBee, affiche les valeurs en direct sur l’interface LCD / clavier, et décide comment bouger les servos qui commandent les stores / volets.

Toute la communication passe par deux modules XBee, donc l’émetteur peut rester dehors pendant que le récepteur est installé à l’intérieur, à côté de l’utilisateur.

02. Mesures & données Surveillance météo

  • Température & humidité : capteur type DHT → °C ambiante et humidité relative (%RH).
  • Vitesse du vent : l’anémomètre génère des impulsions. On compte les impulsions pour estimer la vitesse du vent en km/h.
  • Luminosité : capteur LDR → sert à décider si on doit ouvrir les volets pour laisser entrer plus de lumière naturelle.

L’Émetteur formate ces valeurs dans une trame texte légère et l’envoie via l’UART XBee. Le Récepteur lit cette trame, la décode et met l’affichage à jour immédiatement.

03. Interface utilisateur Homme ↔ Machine

  • Module LCD + clavier (“Manuella”) : affiche les valeurs météo en direct d’une façon lisible pour n’importe qui.
  • Navigation par pages : on peut faire défiler les écrans (température, humidité, vent, luminosité). Un capteur de geste PAJ7620 permet même de changer d’écran sans toucher de bouton.
  • Mise à jour continue : l’affichage se rafraîchit à chaque nouvelle trame reçue en XBee.

Objectif : qu’un utilisateur non technique voie directement “est-ce qu’on ouvre les volets ?” et pas seulement une valeur brute en volts.

04. Actionnement automatique Volets intelligents

L’Arduino Récepteur pilote plusieurs servomoteurs qui commandent les volets / stores. Les décisions se basent sur les dernières données reçues :

  • Température élevée (>30 °C) : volets fermés pour garder la fraîcheur.
  • Plage de confort (≈20–30 °C) : volets à moitié ouverts.
  • Faible luminosité : volets ouverts pour faire entrer la lumière naturelle.
  • Vent fort : volets fermés pour éviter les dégâts.

Donc ce n’est pas juste “je mesure la météo”. Le système réagit et modifie physiquement l’environnement intérieur.

05. Structure du code Arduino (E & R)

Le projet est séparé en deux programmes Arduino : DESPARAIN_Station_Meteo_E.ino (Émetteur) et DESPARAIN_Station_Meteo_R.ino (Récepteur). 


// Pseudocode - Émetteur (E)
// 1. Lire les capteurs
// 2. Construire une trame texte
// 3. Envoyer la trame via XBee

loop() {
    temp = readTemperature();
    hum  = readHumidity();
    wind = readWindSpeed();
    lux  = readLightLevel();

    // Exemple de trame : "T:23.4;H:41;W:12;L:380;"
    String frame = "T:" + temp + ";H:" + hum +
                   ";W:" + wind + ";L:" + lux + ";";

    xbeeSerial.print(frame); // envoi vers le Récepteur
}
  

// Pseudocode - Récepteur (R)
// 1. Lire la trame XBee
// 2. Parser les valeurs
// 3. Mettre l'écran à jour
// 4. Bouger les servos si besoin

loop() {
    if (xbeeSerial.available()) {
        String frame = xbeeSerial.readStringUntil(';');
        parseFrame(frame);        // extraire T,H,W,L
        updateLCD();
        updateServos();
    }
}

Cette séparation (E = mesure + émission, R = réception + décision + action) rend le système modulaire : tu peux changer les capteurs sur l’Émetteur sans toucher à l’interface utilisateur, ou réécrire les règles de pilotage sur le Récepteur sans toucher à la partie extérieure.

06. Compétences acquises Ce que ça m’a appris

  • Liaison radio point-à-point avec modules XBee : création de trames, parsing côté réception, robustesse.
  • Acquisition de capteurs en temps réel et pilotage de servomoteurs sur Arduino.
  • Conception d’une vraie interface utilisateur (LCD + clavier + capteur de geste), pas juste un port série pour ingénieur.
  • Traduire des mesures physiques en actions concrètes sur l’environnement (ouverture / fermeture automatique des volets).
